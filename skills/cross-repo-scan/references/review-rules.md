# 检查规则与证据

对适用规则逐项分析；不适用需给原因。优先新增高风险和受影响关键链路，不把样式建议当生产缺陷。

| ID | 范围 | 必查反证 |
|---|---|---|
| CONTRACT-FIELD | 请求/响应/消息/持久化 JSON 字段、嵌套路径、必填、空值、类型 | 实际序列化策略、注解、别名、适配器、版本路由 |
| CHAIN-PARAM | Web→Java→DAG→Operator→插件 参数传递、单位、枚举 | 显式重命名、模板渲染、插件注册与实际分支 |
| SILENT-FALLBACK | get 默认值、异常吞掉、降级返回成功 | 默认值是否业务允许、输入验证是否提前失败 |
| HISTORY-COMPAT | 历史任务、重试、补跑、滚动升级和回滚 | 已落库参数版本、迁移、双读、目标环境实际版本 |
| ASYNC-STATE | 状态机、并发、锁、幂等、事务与外部副作用 | 锁作用域、唯一约束、重试边界、提交顺序 |
| RESOURCE-BOUND | 无界查询/循环/队列、内存、线程、连接和超时 | 上游限制、批量/分页、取消和资源释放 |
| ERROR-PATH | 部分失败、超时、清理、补偿 | finally、事务回滚、重试是否重复写 |
| CONFIG-DEPENDENCY | 配置键、环境变量、依赖、SQL/迁移、权限边界 | 部署注入、默认配置、兼容版本、授权来源 |

不要声称以上是完整安全审计或跨服务幂等证明。普通 review 也要覆盖变更逻辑正确性和必要回归，不只检查字段。

严重程度：critical 为可达路径下严重数据破坏/广泛服务失效等；high 为关键业务失败或静默错误；medium/low 为影响较小且有边界的问题。必须解释触发条件、可达性和影响，不凭关键词升级。

证据：static 要提供可确定的生产者/消费者、调用路径和无兼容映射的依据；reproduced 要提供隔离输入、命令、退出码、断言与日志；hypothesis 仅为推测。只有复核确认且证据足够才 confirmed。disproved 必须说明反证。默认值掩盖时用不同于默认值的测试输入断言实际消费结果，而不是只断言 200 或 DAG 成功。

稳定 fingerprint 使用 rule_id + repo + 相对路径 + 规范化符号/字段/链路，不用行号做唯一键；跨版本仍须重新验证可达性。基线只标记 existing/new，不自动豁免高危存量。本版不自动接受豁免；如要发布例外，交给独立发布系统审核。
